# 任务并发的科学边界

规划智能体在一次规划中决定最终任务边界，综合权衡科学依赖、单个 Writer 的实现与上下文负担、独立验收与修订的需要，以及并行执行的实际收益。能够放进同一项目只是合并的可行条件，不能单独决定任务边界。规划者简述合并或拆分的主要理由；这些理由用于理解计划，不新增宿主语义或结构验证，也不设置任务数、实验数或工作量阈值。

同一实现的小变体、同一数据上的统计或难以分离的联合运行状态可以合并；工作量明显、目标可独立验收和修订的实验可以拆分。共同图号、同类算法、相同环境或共享固定产物本身不要求合并。无论如何划分，都保留已选实验的原始目标、条件、baseline 和逐项结果。只安排支撑目标所必需的实验，避免为使任务看起来更完整而添加不必要的敏感性分析、消融或其他附加实验。

每个最终任务对应一个 Writer、一个独立 Reporter 和一个完整交付目录。execution unit 只是当前调度与存储使用的一对一任务索引。宿主按规划者声明派发，不推断合并、拆分或科学依赖，不按历史 strong/weak 关系分组，也不创建 Foundation 或冻结共享源码。

确实需要另一任务产生的检查点、数据划分或其他文件时，消费任务通过 `depends_on` 声明生产者和所需文件。上游文件复制到消费方的 `upstream_tasks/`，缺失文件及上游异常同时交给消费方和主持人。当前调度等待上游的 Writer 与 Reporter 流程返回交付后才启动下游，不能把“将来可以共享”当作随意添加依赖链的理由。规划者应同时考虑真实依赖和由此造成的等待；固定产物可供多个独立任务消费，不强制把它们合并。无法定位的依赖或依赖环在实际调度受阻时交给主持人处理。

离线回归可以验证已定稿任务的派发、文件传递、并发与交付，不证明模型一定能正确选择任务边界，也不证明真实论文的复现质量。真实规划中的覆盖、Writer 负担、修订质量与耗时仍需通过实际运行观察。

## 运行与恢复

- 宿主并行提交当前已就绪、无未交付上游依赖的任务。一个任务完成 Writer 后即可进入自己的 Reporter，无需等待其他独立任务；有文件依赖的任务等待上游流程交付。
- 每个任务在自己的工作区内实现、接受独立审查并按主持人的恢复安排修订。其他独立任务可继续运行，任务之间不合并源码或共用 Writer 修订目录。
- 完整和部分恢复都调用 Reporter 自身的缓存检查。旧判决已经终结不代表当前提示词、输入或报告资源仍然有效。缓存有效时不会启动模型，缓存失效只重做必要的审查。
- 部分恢复中的缓存审查与其他未完成 Writer 同时调度；它直接使用已经验证的 Writer 记录，避免为检查 Reporter 缓存先重建 Writer 目录。需要因果修订时只重放旧审查一次，修订后的审查使用新输入。
- 单个审查失败保留该任务的 Writer 交付与其他审查结果，并将异常交给主持人。旧成功记录不能代替当前审查；上游交付或输入变化会影响消费任务的缓存复用，恢复时保留旧运行材料。
- 每次工作流开始时固定宿主执行策略的源码指纹；结束时仍补充实际运行依赖。运行中编辑宿主源码不会污染本轮缓存身份，下次工作流会重新读取策略。

## 如何确认实际并发

`03c_task_writers_start.json` 的 `agent_concurrency` 表示计划中的 Writer 单元数。真正的模型会话数见 `audit/agent_activity.json`，历次运行保存在 `audit/agent_activity_runs/`：

- `active`：当前 Writer、Reporter 与总会话数。
- `peak`：本轮实际启动会话的峰值。
- `sessions`：独立调用的角色、标签、工作目录、起止时间和状态。
- `cached`：复用次数，不计入启动会话或峰值。

CLI 的进度事件包括 `agent.started/completed/failed/cached`，事件文本包含当前两类会话数。当前网站不展示智能体事件流；核对实际并发应查看本地审计记录。计划中有五个任务，不等于任何时刻都应该有五个进程；依赖、缓存和各任务时长都会影响实际数量。强制杀死整个宿主进程可能留下最后一帧运行状态，应结合进程存活与下一轮历史记录判断。

`test_task_agent_process_concurrency.py` 通过真实本地子进程及文件屏障验证调度与工作区隔离；`test_agent_activity.py` 验证运行计数；`test_task_concurrency_resume.py` 验证恢复和反馈屏障。这里的本地替身不调用模型，也不代表 DeepSeek 服务端处理能力或论文复现质量。外部提供商限流、主机 CPU/GPU 资源压力仍需在真实运行中观测。

需要检查真实提供商连接时，可显式执行 `tools/probe_task_agent_concurrency.py --config <项目模型配置.json> --output <项目外的新目录>`。它仅启动 2 个 Writer 与 2 个 Reporter 会话，各自执行一个预置标准库脚本；这会调用模型，但不跑论文。没有持久化密钥时加 `--prompt-key`，隐藏输入只用于本次进程。诊断拒绝覆盖非空目录，并将真实命令、固定输出标记、脚本哈希、统一模型配置及会话重叠检查写入 `summary.json`。诊断成功也不代表提供商内部计算同时进行，或真实论文的科学依赖规划正确。
