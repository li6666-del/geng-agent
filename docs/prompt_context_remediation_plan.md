# 提示词与上下文整改计划

基线：9399d5c。目标是在保留完整论文证据、独立 Reporter、真实执行凭据和必要隔离的前提下，完成提示词审查提出的五项改动。本轮实施与验证均在本地，不提交或推送。

## 决策与实施顺序

1. 科学纠错与裁决边界：将结构修复与有证据的科学纠错区分；完整候选跨后端保真；允许对错误验收目标提出有来源的争议，不允许用争议掩盖独立反证。
2. 实际输入与缓存身份：保存最终发送的提示词和附件身份；缓存依赖角色实际契约，排除审计噪声；科学输出不变时保留无关下游结果。
3. 恢复与执行职责：恢复既有实现并传递当前错误；反馈映射到同版可读证据；按真实恢复原因构造差量；宿主拥有科学进程状态和运行凭据。
4. 科学投影与证据范围：去除确定性重复，保留科学字段及完整原文入口；按任务和缺口选取上下文；多模态降级必须保留可见范围记录。
5. 报告交付与质量/成本对照：Editor只转述终态与可核实事实；对固定跨论文证据开展受控真实模型对照，分别统计科学误判、不必要重跑、读取与调用成本。

第1、3、4项的独立模块并行实施。第2项为缓存和对照验证的前置条件；第5项在相关科学指令冻结后执行，再对集成复核的补充修改运行完整回归。

## 分工与边界

- 上游实施：科学修复、API一致性、证据可见范围、分析提示投影和任务/Thesis指导。
- Writer实施：Foundation恢复、Writer恢复反馈、执行状态协议、分支提示与相关回归。
- Reporter/Editor实施：验收目标争议、Reporter恢复、已核实报告事实和相关回归。
- 主代理：缓存身份、实际输入记录、集成、独立复核、跨论文测量与结果记录。

## 验收

- 结构错误不丢科学值；scope/override等科学冲突有合法纠错路径，不靠删除完整科学项过关。
- 错单位、错区间或非论文目标不会强制错误比较；方法替代、排序反转和严格精度失败仍然保留。
- 最终brief与实际stdin一致；相关契约变化使缓存失效，无关角色和审计元数据变化不扩大重算。
- 失败恢复可见旧实现、具体错误、同版证据；在途实验不重复启动，补环境不重建已完成任务。
- 确定性去重前后科学字段和可追溯来源保留；缺失原文、图片降级不会被说成论文未披露。
- 报告正文不产生竞争裁决或虚构有效运行次数；第三方可追踪报告依据。
- 工程测试与真实模型对照分开报告。字符减少不等于费用减少；未知用量不记零。固定证据对照不等于完整论文复现成功率。
