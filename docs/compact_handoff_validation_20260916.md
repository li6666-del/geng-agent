# Writer 上下文与重复交付精简（2026-09-16）

## 范围

本次处理两项耗时来源：Writer 输入重复堆叠，以及 Writer、Reporter、Editor 重复撰写相同内容。保留 GPT6 medium、独立 Reporter、宿主执行回执、科学停止策略和编辑智能体生成的两份中文报告。

## 实现

1. `task_writer_inputs.py` 为单任务和复合执行单元生成 `paper_evidence/writer_input.json`。任务与验收条件保留完整对象，事实按明确 ID 或类型和名称选取；没有 20 条上限。仅合并完全相同的记录，同 ID 的冲突值仍保留。任务依赖、共享组件和实验记录可按索引访问；未解析引用显式列出。
2. 完整原文、全部解析文本、全部页面及最终分析文件仍位于证据目录。任务包是阅读入口，不是科学边界；遇到歧义、缺项、冲突和跨页引用需要查原文，声明参数缺失前必须搜索全文。宿主不推断同义表达，不替智能体认定事实或结果。
3. 初始 brief 不再内联任务 JSON、事实预览、论文的多份截断预览、完整实验索引和通用运行接口。运行接口移到 `runtime_reference.md`；原有任务证据 JSON/Markdown 改为导航指针。图片只按字节完全一致去重，原始文件及映射不变。
4. Writer 必需交接只有 `task_agent_result.json`，包含实现选择、参数来源、假设、差异、迭代理由、产物和宿主回执引用。无需重复 Markdown 或抄写宿主已记录的次数、退出码、耗时。
5. Reporter 保留一次结构化科学判断：`decision_reason`、逐主张观察、数值比较、已核实事实、限制及必要的因果重跑说明。不再请求 `comparison_summary`、`report_explanation` 或独立叙述报告。旧字段继续兼容读取。
6. Editor 仍独立生成结果对比报告和本地复现报告。Writer 自述、Reporter 判断和宿主运行记录分开标注来源；运行次数与耗时来自宿主回执，未知不补造。中文、逐任务事实与假设、结果差距、原图和本地图、人工作业建议等要求保留。
7. 新的任务包构造逻辑进入 Writer 缓存策略哈希；Reporter、Editor 提示词版本更新，旧判断不会被当作本次新提示词下的结果。

### 判决范围的实际不稳定

T1 和 T3 前后均为 `not_reproduced`。T2 的主张 c4（项数提高带来的总体精度改善）和 c5（Radau 的宽区间优势）前后均获条件性支持，数值记录也相近；但总标签从 `reproduced_with_assumptions` 变为 `not_reproduced`。

两次 Reporter 都发现同一 Fig.1(a) 中 Chebyshev 第一类的局部排序未复现。旧 Reporter 将它视为 T2 指定 c4/c5 之外的附带失败，新 Reporter 将其纳入 T2 总判决。当前要求把任务契约作为导航、允许依据原文补充判断，因此这里存在“任务验收范围”与“同图完整结论范围”的解释差异。不能把新标签改回去以美化对照，也不能认定这是上下文压缩导致的信息丢失：相同原文、原任务字段和负面数值证据都保留了。

这次运行能验证交接可用、失败未被掩盖，不能证明科学总判决稳定。后续需要用固定代码和测量材料重复核验任务范围，明确指定主张与额外观察怎样影响任务标签；这应由科学智能体给出显式理由，不能交给 Python 对自然语言作同义判决。该问题本次如实记录，没有增加额外裁判 Agent 或强制对齐基线标签。
