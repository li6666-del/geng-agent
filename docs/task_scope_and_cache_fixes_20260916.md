# 任务验收范围、依赖声明与 Foundation 缓存修复

## 本次约定

验收仅围绕指定复现任务的目标及检验目标所必需的科学条件。原文仍是事实与方法的依据，但阅读整篇论文、检索到同图排序，都不自动扩大任务目标。程序只负责结构、证据路径、版本兼容性和缓存完整性；科学相关性与最终判决仍交给智能体。

## 已实施

1. **目标范围贯通规划、执行、审查与报告。** Planner 明确目标与适用条件；Writer 不为范围外发现增加实验；Reporter 的核心观察与数值比较只针对目标。目标内未列入 Designer ID 的算法错误仍可判失败，需解释 `goal_relation`。范围外发现使用可选 `additional_observations`，保留观察、范围说明和证据，不改变任务结论或触发重跑。
2. **消除同图排序带来的额外验收。** 按图号或指标检索的排序锚点改为候选证据，移除最高优先级、预设失败标签和猜测原因要求，由智能体判断它与任务目标的关系。
3. **保留范围外发现的追溯。** 新字段贯通 Reporter 规范化结果、聚合结果、JSON Schema 和 Editor 输入；聚合保留 `provenance_base`，可以定位工作区相对证据。范围外证据不可用只产生提示与可用性标记，不损害目标内有效结果。Editor 在本地复现报告单列，必要时加入人工核查建议，不重新裁决。
4. **依赖按锁定版本兼容性判断。** 原来要求声明表达式完全相同，现在要求可信环境锁已验证的安装版本同时满足锁定约束和 Writer 约束。包名、extras、marker、安全来源和 probe 状态仍受约束；缺失或不兼容版本不会放行。无需模型改写等价依赖声明。
5. **缩小 Foundation 缓存边界。** 从整个 `writer_lineage.py` 的哈希改为 Foundation 实际使用的投影、依赖分析函数及专用策略指纹。Writer/Reporter 无关策略变化不再牵连 Foundation；论文、共享事实、接口、数量、修订、相关运行时逻辑变化仍失效，冻结代码哈希检查仍保留。

## 本地验证

- 验收、Reporter、Editor、Schema 与 Pipeline 最后一轮：82 项通过、2 项跳过、16 个子测试通过。
- 依赖与环境回归：81 项通过、6 项跳过、96 个子测试通过。只读使用上次真实 `03a_environment.lock.json`，在外部临时目录重放 `numpy==2.5.3`、`scipy==1.18.1` 声明，检查结果为空问题列表。未安装依赖。
- Foundation 缓存、共享范围、快照、装配与 lineage 回归：98 项通过、5 项跳过、10 个子测试通过。覆盖无关策略继续复用、科学输入变化失效、冻结代码被修改后拒绝复用。
- 训练产物与消费者链的 6 项测试在正常本地权限下全部通过。首轮两项在外层沙箱中报 `Could not find home directory`；复查实际 stderr 后重跑，未修改产品逻辑规避。
- 测试组有交集，不将这些数字直接相加。测试运行环境与临时案例位于项目外，已有论文案例及历史报告未修改。

这些测试证明路由、数据保留、版本校验和缓存边界按预期工作，不证明模型必然正确理解所有论文目标。本轮未调用付费模型、未重新运行论文实验，也未重新验证网页。

## 恢复兼容性

Foundation 指纹格式升级后，旧键无法证明与新键等价，因此旧缓存会失效一次；没有迁移旧键或跳过完整性校验。之后纯 Writer/Reporter 策略变化不再导致 Foundation 无效重建。

本次同时更新了 Writer 提示词和共享停止政策，它们仍属于 Writer 现行缓存键。因此主动恢复旧案例时，Writer 也可能重新进入执行流程，不能承诺仅重审而不重跑。Reporter/Editor 的提示词版本同步升级，旧科学标签不会被直接当作新验收政策的结果。历史文件继续保留，本次没有启动任何旧案例恢复。
