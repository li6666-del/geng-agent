# 通用复现整改实施计划

本轮目标：完成独立审查提出的五项整改，保留完整论文证据、独立科学审查、必要隔离和正常科学失败终态。当前工作区已有的大量未提交修改是实施基线，不回滚、不覆盖无关修改。

## 决策与依赖

1. 科学交接：科学值比较保留符号、指数、类型和 Unicode；最终任务完整快照替换旧规格，历史保留在 audit；Reporter 新反证不丢失，缺失支持证据只能形成不确定性。
2. 运行关联：可信运行入口记录 run ID、代码/配置/环境/输入产物摘要、退出状态及输出摘要；单任务和 compound 均按运行代际交付，缓存复用必须说明依赖。不得通过恢复旧源码后继续接受新输出。
3. 共享边界：仅跨执行单元需要一致的组件及依赖进入 Foundation；共享训练产物显式生产/消费；有论文证据的共享缺陷进入定点修订，新版本仅影响消费者。
4. 恢复与停止：使用执行单元及科学依赖摘要恢复；补包不清空全部沙箱；重复判断依据实际输入、修改和失败证据，既允许同位置的新修复，也停止无进展循环。
5. 交付与评测：生成可操作 README、可重建依赖及来源；在干净环境运行小规模交付验证；累计记录 Codex/实验成本；建立跨论文类型的成对科学校准样例与盲评入口。

依赖顺序为 1 → 2 → 3/4 → 5；彼此独立的代码与测试可以并行准备。用户已明确改为本地执行和验证，AGENTS.md 同步移除远端前置要求。测试临时目录和 case 输出保存在源码目录外。

## 验收场景

- 数值、公式符号、指数和中文身份不会在合并时碰撞；最终稿能够撤销旧假设和关系。
- 新 unsupported 不会被删除；无观察的 supported 不会授予 reproduced；普通数值小于 10 倍不独立引发重跑。
- 旧 CSV + 新源码 + 失败运行不能变成当前成功；图样变化不迫使数值缓存失效。
- 一个训练产物由两个评估共享；私有评价代码可修；共享噪声归一化错误能定点修订且无关单元保留。
- A 完成、B 缺包时 A 不重跑；同一函数中的两个不同修复可继续，同状态重复停止。
- 第三方仅凭交付包完成安装和 smoke；环境重建失败独立报告，不篡改科学终态。
- 新运行加缓存恢复的累计成本不归零、不重复累计；成对校准覆盖样本外形、方法排序、机制替换、严格精度和信息不足。

## 分工

- 主代理：运行凭据、局部恢复、停止策略、共享修订集成、本地验证及最终审查。
- 科学交接代理：合并、任务最终快照、Reporter 归一化、材料性校准样例。
- 共享科学代理：Foundation 范围、关系编译、多 experiment binding、定点修订接口。
- 交付评测代理：交付文档/环境重建、成本事件、基线指标、报告事实块。
