# 按任务的智能体工作流

## 本轮目标

宿主负责工具执行、信息传递、实际运行记录、资源与主动停止。科学内容由专业智能体理解，异常恢复由主持人决定。删除 Foundation，任务边界由规划者一次定稿。

## 实施顺序

1. 删除 Foundation 生成、冻结、修订、安装和缓存路径；保留通用文件操作工具。
2. 规划者权衡科学依赖、单个 Writer 的理解/实现/调试负担、独立验收与修订能力和并行收益，决定合并或拆分并简述理由；任务数越少或越多都不是目标。同一实现的小变体和同一数据的简单统计可合并，工作量明显不同且可独立完成的目标可拆分。保留全部必要子实验条件、验收目标和结果；每个最终任务对应一个 Writer、一个独立 Reporter 和一个交付目录。
3. 宿主不按 strong/weak 自动分组。有必要的跨任务文件通过消费任务的 `depends_on` 声明，交付后复制到 `upstream_tasks/`，缺失情况同时传递。
4. 删除固定修复次数、代码变化指纹、Foundation 所有权路由和 Writer 交付前审批。观察失败不会终止进程；可读产物不会因模型退出码而被直接丢弃。
5. 用离线回归验证交接、并发、恢复、打包与报告调用链。模型响应使用替身；真实本地子进程验证记录、主动取消和小型训练产物传递，不运行真实论文复现。

## 规划工作量与依赖

- 共享公式、库、环境、固定数据或检查点不自动要求合并；需要共同迭代的科学状态可留在一个任务中。已有固定文件可通过 `depends_on` 传递。当前下游等待上游 Writer/Reporter 流程交付，拆分时需考虑这段串行等待，不能为追求并行任意切碎工作或凭空增加依赖。
- 每项实验应服务于所选论文主张，或解决足以影响结论的歧义。不为完整感附加参数扫描、消融、渐近扩展或演示；必要基线、对照、统计核查和论文条件仍保留。简单派生统计复用已有输出，常规实现自检由 Writer 自行组织。
- 划分理由写入现有计划概述或任务说明，使用简短中文；不增加必填字段、评分表、任务数量上限或额外规划阶段。宿主按最终任务与文件依赖派发，不审查理由、不自行合并或拆分。

## 恢复与交付

- Reporter 直接获得 Writer 材料及原始异常。输出说明不完整不等于应当重跑；科学错误是否需要修复由智能体决定。
- 主持人的修复工具失败会带着异常返回主持人。协调模型不可用时保留未解决状态和正在运行的任务，不冒充模型发出“停止”结论，不自动无限重试付费调用。
- 用户停止会取消所属进程；同目录的活跃执行者、操作系统隔离、凭据隔离、文件路径范围和环境安装锁继续保留。这些是执行边界，不是论文或输出内容验收。
- 独立任务直接并发使用 GPU，宿主只选择设备，不持有 GPU 独占锁，不等待其他任务释放 GPU。运行错误随实际执行记录交给智能体处理。
- 恢复时保留旧产物和源码；计划或上游输入变化可使旧缓存不再直接复用，但不会删除原运行现场。上游文件及异常随消费任务交付。
- 每个任务保存完整实现。没有共享源码冻结、跨 Writer 代码合并或独立环境再验收；打包不可用可由主持人转为部分交付并推进报告。
- JSON Schema 用于字段说明和生成辅助，不是宿主科学内容验收。需要实际派发时仍要能定位目标任务、工具或文件；无法执行的原始材料和错误交给主持人处理。

## 验证边界

离线测试只能证明提示词传递、调度、交接、取消、恢复与文件交付行为；不能证明规划者总能合理划分任务，也不能证明真实模型能完成论文复现。任务划分对上下文负担、科学结论覆盖、运行成本和局部修复质量的影响仍需后续真实论文实验评估。

历史 case、旧文档和 Web 展示中的 Foundation 名称可能用于读取旧记录；新工作流不会创建或执行该阶段。
